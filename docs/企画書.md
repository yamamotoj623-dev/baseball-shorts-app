# 野球マネジメント・シミュレーション 企画書

> テキストベースの野球育成シミュレーション。プレイヤーは監督／球団GMの目線で、
> 選手を獲得・育成・編成し、ペナントレースをシーズン単位で進めていく。
> リアルな3D描写は持たず、「数字・編成・育成のおもしろさ」で勝負する。

最終更新: 2026-06-09

---

## 1. コンセプト

- **一言で**: 「自分だけのオリジナル球団を、数字で育てて頂点を目指す」
- **原体験**: 昔のPCブラウザゲーム（選手にステータスを配分→試合をシミュ→ペナント進行）。
  + やきゅつく／プロ野球チームをつくろう、ウイイレのマスターリーグ的な
  「交渉して選手を獲得しチームを育てる」感覚。
- **想定プラットフォーム**: まずWeb（PC・スマホブラウザ）。将来的にPWA／Steam／ネイティブ化を検討。
- **コアループ**:
  1. 選手を獲得・編成する（GM視点）
  2. 試合をシミュレーションで回す（テキスト実況）
  3. 結果から成長・順位・資金が変動
  4. オフシーズンに補強・育成方針を決める → 翌シーズンへ

## 2. 「稼げるか」への現実的な見立て

### 良い面（このジャンルの強み）
- **個人開発と相性が最高**: 3D不要。グラフィックではなくロジックとバランスで戦える。
- **コア層のLTVが高い**: シミュ系は「長く遊び続ける」ユーザーが多く、継続課金・買い切りリピートが見込める。
- **実例がある**: 海外の *Out of the Park Baseball (OOTP)* は小規模スタジオ発で毎年有料版が売れている。
  国内も「育成シミュ」は根強いファンがいる。

### 厳しい面（先に直視する）
- **作ることより「知ってもらうこと（集客）」が何倍も難しい**。個人ゲームの大半はほぼ無収入。
- **テキスト系は最初の数分の離脱が勝負**。淡々と進む心地よさと、初動の「掴み」を両立する必要がある。
- **野球の権利問題**: 実名選手・実在球団・NPB/MLBロゴは権利が絡む。
  → **最初はオリジナル選手・架空リーグで作る**（権利リスクゼロ、後述）。

### 結論
> 「副業で月数万〜」は十分狙えるレンジ。ただし **小さく出して数字を見て育てる**のが大前提。
> 一発の大ヒットを狙うより、コア層に刺さる完成度を積み上げて、広告＋課金＋（将来）買い切りで積む。

## 4. 差別化（なぜこれを選ぶか）

1. **GM/監督の"経営×編成"に寄せる** — 試合操作ではなく「誰を獲り、誰を育て、どう戦力を組むか」。
2. **テキスト実況の心地よさ** — 速い／淡々／でも要所で熱い。ログを読む快感を設計する。
3. **オリジナル選手の自動生成 + 自分で配分** — 「自分だけのチーム」感を最大化。
4. **放置・スキマ適性** — 1試合数十秒で消化、まとめてシーズンスキップも可。スマホ前提のテンポ。

---

## 5. 収益モデル（フェーズで切り替える）

### フェーズA: 無料Web + 広告（最初はここ）
- 完全無料で公開、まず遊んでもらい数字（リテンション・滞在）を取る。
- シーズン区切りやリザルトに**動画リワード広告**（任意視聴で報酬）。
- 目的は収益より**「面白いか／続くか」の検証**。

### フェーズB: 軽い課金（IAP）を追加
- 売るのは「時短」と「快適さ」で、**pay-to-winにしない**のが鉄則：
  - スカウト枠拡張 / ドラフト指名権の追加
  - シーズン一括スキップ・倍速
  - 広告非表示パス（買い切り）
  - 着せ替え（ユニフォーム・球団エンブレム等のコスメ）

### フェーズC: 買い切り or サブスク（実績が出てから）
- Steam等で機能拡張版を買い切り（OOTPモデル）、またはコア層向けサブスク。

### 数字感（あくまで目安）
- 広告: DAU 1,000人 × eCPM 数百円規模で月数千〜数万円レンジ。**集客がすべて**。
- 課金: コア向けゲームは課金率1〜3%が現実的。DAUと客単価で積む。

## 6. MVPスコープ（最初に作るもの）

「面白さの核」を最速で検証するため、**試合シミュ → 短いペナント → 育成** の順で最小実装。

### MVP-1: 試合シミュレーションの核
- オリジナル選手のステータス（例: ミート/パワー/走力/守備/球速/制球/スタミナ）。
- 2チームで1試合を**イニング単位でテキスト実況**しながらシミュレート。
- 結果（スコア・成績）が出る。**まず「この実況を読むのが面白いか」を確かめる**。

### MVP-2: ミニ・ペナント
- 数チーム・十数試合のミニリーグを自動消化、順位表が動く。

### MVP-3: 編成・育成
- 選手にステータスを配分／成長、ドラフト・獲得の最小版。GM体験の入口。

> ※ 今回のリクエストは企画なので、コードはこの企画確定後に MVP-1 から着手する。

## 7. 技術スタック（現状の構成を活かす）

- **フロント**: Vite（+ React 想定）。スマホブラウザ最適化。
- **バックエンド**: Google Apps Script（GAS）＝ `.env.local` の既存エンドポイント。
  - メリット: **無料〜低コスト**で副業向き。データ保存（スプレッドシート）も手軽。
  - 注意: 高負荷・低レイテンシには不向き。シミュ計算は**クライアント側**で完結させ、
    GASは「セーブデータ保管・ランキング」など軽い用途に限定する設計が安全。
- **将来**: 規模が出たら Supabase / Cloudflare 等へ移行余地を残す。

> ⚠️ セキュリティ: `.env.local` に GAS のエンドポイントと認証トークンが平文で入っている。
> これは `.gitignore` で**確実に除外**し、リポジトリに push しないこと（後述のTODO）。

## 補足: リスクと割り切り

- 「稼ぐ」を急ぐと作り込み過多で公開が遅れる → **まず小さく出して数字を見る**。
- 集客は別スキル。X（Twitter）等で開発過程を発信し、公開前にファンを作るのが効く。
- 完璧主義を捨て、**コアループが面白いかだけに集中**するのが副業成功の近道。
